# Переход с v0.1.1 на v0.2.0 на macOS (с сохранением данных)

Пользовательская папка может по-прежнему называться `invoiceshield-v0.1.0`: это нормально, название папки не равно версии приложения.

1. В терминале, где работает Uvicorn, нажми `Control + C`.
2. Создай резервную копию базы:

```bash
cd ~/Downloads/invoiceshield-v0.1.0
cp invoiceshield.db invoiceshield-backup-before-v0.2.0.db
```

Если база находится в другом месте, копировать нужно **её**. Если файла `invoiceshield.db` нет, запусти `pwd` и `ls -la` и сначала найди свою рабочую директорию.

3. Распакуй архив обновления в **текущую папку**:

```bash
unzip -o ~/Downloads/invoiceshield-upgrade-v0.2.0.zip -d .
```

4. Активируй окружение, обнови библиотеки:

```bash
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

5. Создай первого администратора. На Mac пароль скрыт при вводе — это нормально:

```bash
python -m scripts.manage_users add --username admin --role admin
```

Используй отдельный пароль длиной **от 12 символов**, не пароль от Mac/GitHub.

6. Запусти проверки и сервер:

```bash
python -m pytest -q
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

7. Открой `http://127.0.0.1:8000/login`, войди и убедись, что старые счета видны. При запуске создаются только новые таблицы авторизации; старые таблицы остаются нетронутыми.

**Не выполнять:** `rm invoiceshield.db`, `docker compose down -v`, `git clean -fdx`. Они могут удалить данные.

Дополнительно создаём аналитика (с отдельным паролем):

```bash
python -m scripts.manage_users add --username analyst --role analyst
```

Если уже применялось обновление, повторное создание `admin` сообщит, что пользователь существует. Удалять таблицу `users` ради этого не нужно.

## Откат

Перед откатом остановить сервер. Старую версию можно восстановить поверх исходников, а новую резервную копию БД (`invoiceshield-backup-before-v0.2.0.db`) использовать только после осознанного решения: восстановление резервной копии удаляет операции, сделанные после её создания. Старый код проигнорирует добавленные таблицы пользователей; он **не защищает** API авторизацией, поэтому откатывать только для локальной диагностики.
