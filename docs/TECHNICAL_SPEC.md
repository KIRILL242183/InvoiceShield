# Техническое задание — InvoiceShield v0.1.0

## 1. Назначение

Локальная демонстрационная система выявления **сигналов** возможного мошенничества при оплате счетов контрагентов. Она не подтверждает мошенничество и не инициирует реальные платежи.

## 2. Роли будущей системы

- Финансовый специалист: регистрирует поставщиков и счета, изучает причины риска.
- Комплаенс-аналитик: расследует предупреждения.
- Администратор: управляет доступом и политиками.

**Ограничение v0.1:** ролей и аутентификации пока нет. Все маршруты открыты пользователю, имеющему доступ к локальному серверу. Нельзя публиковать сервис в интернет или вводить настоящие финансовые данные.

## 3. Функциональные требования (реализованы в v0.1)

| ID | Требование | Критерий приёмки |
| --- | --- | --- |
| FR-01 | Создание поставщика | HTTP POST `/api/suppliers` возвращает 201 и идентификатор |
| FR-02 | Защита от повторного имени поставщика | Повторное имя возвращает HTTP 409 |
| FR-03 | Регистрация счёта | POST `/api/invoices` сохраняет его, рассчитывает риск |
| FR-04 | Контроль банковских реквизитов | Несовпадение с реестром даёт +70 |
| FR-05 | Поиск повтора номера | Совпадение номера в рамках поставщика, без учёта регистра, даёт +60 |
| FR-06 | Выявление крупной суммы | Сумма строго больше 1 млн ₽ даёт +35 |
| FR-07 | Веб-панель | На `/` видны формы, список счетов, риски, события |
| FR-08 | API | Доступны `/docs`, `/api/suppliers`, `/api/invoices`, `/api/audit` |
| FR-09 | Журнал действий | Создание поставщика и проверка счёта фиксируются с ID |
| FR-10 | Проверки | `pytest` проверяет основные бизнес-правила и ошибки |

## 4. Расчёт риска

Формула: `score = min(100, сумма баллов сработавших правил)`. Уровень LOW: 0–29; MEDIUM: 30–59; HIGH: 60–100. Правила не обучены на реальных данных и не отражают частоту мошенничества. Сигналы требуют независимой проверки человеком.

## 5. Нефункциональные требования

- Основной язык — Python 3.12+.
- Все денежные величины сохраняются как целые копейки, без `float`.
- Данные проверяются на уровне Pydantic.
- Для разработки поддерживается SQLite, для контейнерного демо — PostgreSQL.
- Простая контейнеризация Docker Compose; привязка web-порта только к `127.0.0.1`.
- Время хранится в UTC (в интерфейсе v0.1 время без указания пояса — будет улучшено).

## 6. Сознательные ограничения и технический долг

- Нет логина, разграничения ролей, CSRF-защиты, TLS и защиты от брутфорса: **локальное демо, не продакшен**.
- Изменение реквизитов эталонного поставщика через UI не реализовано.
- Номер не уникален намеренно: дубликат должен сохраняться и отображаться как подозрительный.
- Проверка дубликатов на записи не имеет блокировки конкурирующих транзакций.
- Таблицы создаются через `create_all`; миграции Alembic запланированы далее.
- Журнал событий внутри той же БД не является защищённым от подмены или полноценным security audit.
- Статистика на главной странице рассчитывается по последним 100 счетам (ограничение первой версии).
- Нет загрузки документов, авторизации, интеграции с ERP или ML.
- Поддерживается единственная компания и одна валюта (RUB).

## 7. Следующий этап
