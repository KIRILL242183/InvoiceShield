# InvoiceShield 1.0.0 — протокол технической приёмки

Дата: 29 октября 2026 года. **Локальная портфолио-демонстрация, не production**.

## Подтверждённые проверки

- ✅ Pytest: полный набор регрессионных тестов, включая новый сквозной тест.
- ✅ Python compileall для `app` и `scripts`.
- ✅ Реальный Uvicorn: GET `/health` и GET `/ready` отвечают HTTP 200 и версией 1.0.0.
- ✅ Функциональные тесты проверяют роли, CSRF, риск, инциденты, экспорт без реквизитов и предпросмотр PDF без сохранения.

## Осталось подтвердить отдельно

- ⏳ Финальные GitHub Actions для релизного коммита (включая Docker/PostgreSQL); см. Pull Request.
- ⏳ Полная ручная браузерная проверка на Mac: загрузка PDF с диска, клавиатурная навигация, экраны 390px/1365px. Автоматический браузер в текущей среде блокируется политикой, поэтому не заявляем, что он был протестирован.
- ⏳ Проверка восстановления SQLite на компьютере пользователя.

## Ограничения

- Баллы риска — эвристики, не оценка вероятности мошенничества; деньги не переводятся.
- Нет OCR сканированных PDF, MFA, изолированного PDF воркера, Alembic-миграций, multi-tenancy и независимого security review.
- Не публикуйте экземпляр приложения в интернет и не загружайте реальные данные без отдельной оценки безопасности.

## Перед показом работодателю

1. Используйте синтетические счета и отдельную демобазу, не рабочую локальную БД.
2. Войдите под admin и создайте подозрительный счёт.
3. Откройте кейс, назначьте analyst, измените статус и добавьте комментарий.
4. Проверьте отказ в экспорте для analyst; покажите PDF preview и аналитику.
5. Покажите GitHub Actions и расскажите об известных ограничениях.
