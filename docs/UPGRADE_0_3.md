# Как обновить InvoiceShield v0.2.0 → v0.3.0 на macOS

Не удаляйте существующую папку и файл базы. Архив `InvoiceShield-v0.3.0-update.zip` содержит **только исходный код, тесты и документацию**.

## 1. Остановите приложение

В терминале с работающим сервером нажмите `Control+C`.

## 2. Сохраните резервную копию базы

```bash
cd ~/Downloads/invoiceshield-v0.1.0
pwd
ls -lh invoiceshield.db
cp -p invoiceshield.db invoiceshield-backup-before-v0.3.0.db
```

Важно: первоначальная папка по-прежнему может называться `invoiceshield-v0.1.0`. Это нормально. Если `invoiceshield.db` не найден — не запускайте миграцию, пока не найдёте рабочую базу. При `DATABASE_URL` в переменной окружения резервную копию сделайте **именно той** базы, на которую он указывает.

## 3. Распакуйте архив обновления

Скачайте `InvoiceShield-v0.3.0-update.zip` в Downloads, затем выполните:

```bash
unzip -o ~/Downloads/InvoiceShield-v0.3.0-update.zip -d .
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Обновление не меняет существующие пароли: **создавать пользователей повторно не нужно**.

## 4. Обновите структуру базы (важно)

```bash
python -m scripts.migrate_v03
```

Команда добавляет таблицы `incidents` и `incident_events`, затем создаёт по одному инциденту для **старых** счетов, чей сохранённый риск `MEDIUM` или `HIGH`. Ничего не пересчитывает и не изменяет прежние счёта. Команду можно безопасно запускать повторно; существующие инциденты не дублируются.

## 5. Проверка и запуск

```bash
python -m pytest -q
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

В браузере откройте `http://127.0.0.1:8000/login`, войдите как раньше и нажмите **«Расследования»** в меню слева. На странице создайте счёт с изменёнными реквизитами, откройте созданный инцидент и переведите его в статус «На проверке».

Если видите ошибку `no such table: incidents`, вы пропустили шаг 4 или приложение использует другую базу (проверьте `DATABASE_URL` и текущую папку).

## Откат

Остановите сервер. Восстановите файлы версии 0.2 из прежнего архива, **не удаляя** существующую базу: старый код не обращается к новым таблицам. Резервная копия БД нужна лишь в случае восстановления данных: её использование удалит изменения, сделанные после резервного копирования. Отдельные миграции с удалением таблиц здесь не предоставляются.

### Ограничения

v0.3 — локальный учебный MVP, а не промышленное решение. Нет полноценной системы миграций Alembic, многоарендности, MFA, ограничений запросов и защиты от независимого изменения БД администраторами. Не используйте реальные финансовые данные и не публикуйте сервер в интернете без отдельного security-review.
