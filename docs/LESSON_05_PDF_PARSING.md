# Урок 5. Надёжнее извлекаем поля из PDF

## Задача

Версия v0.4 читала PDF и искала первое совпадение регулярным выражением. В некоторых счетах это приводило к неправильной сумме (например, `1 234 567,89`) или неполным реквизитам. В v0.5 разделены две задачи: **извлечение текста из PDF** (`extract_draft`) и **семантический разбор текста** (`parse_invoice_text`).

## Читаем путь запроса

1. `app/routes_pdf.py`: только авторизованный пользователь с валидным CSRF-токеном передаёт PDF.
2. `app/services/pdf_import.py:extract_draft`: ограничивает размер, количество страниц, проверяет структуру и извлекает текст.
3. `parse_invoice_text`: ищет значения только возле известных меток (`Счёт №`, `Итого`, `Р/с`, `Дата`, `Invoice No`, `Total`, `IBAN`).
4. `_parse_money` приводит `1 234 567,89`, `1.234.567,89`, `1,234,567.89` к одному виду `1234567.89`.
5. Если в документе обнаружены противоречия (например, две разные итоговые суммы), соответствующее поле **остаётся пустым** и пользователь видит предупреждение.
6. Веб-страница показывает извлечённые поля даже при пустом реестре поставщиков. Сохранение счёта выполняется **только отдельным подтверждением**.

## Почему безопаснее не угадывать

Инвойс может содержать сумму без НДС, сумму с НДС, итог и сумму предоплаты. Автоматический выбор первого числа опасен. В текущей версии несколько разных значений для одного поля дают конфликт; человек должен выбрать правильное. Это снижает риск ложного подтверждения мошеннической операции.

**Важно:** PDF может быть злонамеренным, независимо от наличия `%PDF-` и ограничений размера. `pypdf` работает в веб-процессе — это приемлемо только для учебной локальной демонстрации с доверенными документами. Для бизнеса нужны изолированный worker/container, CPU/RAM/time limits, сканирование содержимого, очередь задач, дополнительное тестирование и полноценный threat model. OCR ещё не реализован. Регулярные выражения не дают 100% точности, например для таблиц с нестандартной версткой.

## Практическое упражнение

Открой `app/services/pdf_import.py`, функцию `_parse_money`, и запусти:

```bash
python - <<'PY'
from app.services.pdf_import import parse_invoice_text
for text in ("Итого: 1 200,50", "Total: 1,200.50", "Итого: 1,200"):
    draft = parse_invoice_text(text)
    print(draft.amount_rub or "Требует ручной проверки", draft.warnings)
PY
```

`1,200` отклоняется как неоднозначная запись (1200 или 1.2), а первые два выражения корректно преобразуются в `1200.50`.

Далее изучи `tests/test_pdf_formats.py`. Измени тестовую сумму и запусти `python -m pytest -q tests/test_pdf_formats.py`. Посмотри, почему тест проходит или падает.
