# Операционная инструкция: резервные копии и восстановление (v0.8)

> **Внимание:** копии содержат банковские реквизиты поставщиков, хеши паролей, сессии и события аудита. Храните их в защищённом каталоге, **никогда** не прикладывайте к GitHub Issues/PR, не отправляйте в чат и не коммитьте. Скрипт не шифрует резервные копии и не заменяет управление ключами.

## Локальная SQLite

В каталоге проекта с активным `.venv`:

```bash
# Онлайн-резервное копирование при работающем сервере.
python -m scripts.backup_sqlite backup --output ~/InvoiceShield-private/backups/invoiceshield-2026-10-29.db

# Проверка целостности SQLite + минимально необходимой схемы.
python -m scripts.backup_sqlite verify --input ~/InvoiceShield-private/backups/invoiceshield-2026-10-29.db

# Неразрушающее восстановление в НОВЫЙ путь.
python -m scripts.backup_sqlite restore \
  --input ~/InvoiceShield-private/backups/invoiceshield-2026-10-29.db \
  --to ~/InvoiceShield-private/restored-for-review.db
```

Скрипт применяет `sqlite3.Connection.backup()` — это SQLite API для согласованного снимка работающей базы. `cp` работающего файла `.db` может пропустить журнал WAL и привести к несогласованной копии. После создания копия проходит `PRAGMA integrity_check` и проверку таблиц. Права доступа к созданному файлу: `0600` (Unix), уже существующие файлы не перезаписываются. Но проверка целостности **не** доказывает корректность всех бизнес-данных, и она не защищает от потери данных после момента резервного копирования.

**Для возврата к копии**: полностью остановите сервис, убедитесь, что никто не работает с базой, сделайте дополнительный снапшот текущей БД, вручную задайте `DATABASE_URL=sqlite:////полный/путь/к/restored-for-review.db` или согласованно переключите файлы. Скрипт `restore` намеренно не подменяет рабочий файл. Старые сессии из снимка могут оставаться действующими, если срок ещё не истёк: при реальном инциденте предусмотрите их отзыв.

## Docker / PostgreSQL

Команда Python выше для PostgreSQL **не подходит**. Демонстрационный пример:

```bash
# Создаёт локальный файл на хосте; не переносите его в репозиторий.
docker compose exec -T db pg_dump -U invoiceshield -d invoiceshield -Fc > ~/InvoiceShield-private/pg-backup.dump
```

Пароль хранится в локальном `.env`, а команда `pg_dump` запускается внутри контейнера с уже настроенной аутентификацией. Восстановление проводите в **новую пустую** тестовую БД через `pg_restore`, а не поверх активной базы. Нужны отдельные планы шифрования, ротации и тестового восстановления, если в будущем будут реальные данные.

## Минимальный регламент

- Еженедельно выполняйте резервное копирование в отдельный приватный каталог и проверку целостности.
- Минимум раз в месяц тестируйте восстановление в отдельную БД.
- Перед обновлением версии создавайте копию; не отправляйте её в PR и CI.
- Не держите каталог копий рядом с публичными исходниками.
- При появлении реальных данных потребуется безопасное хранение, шифрование, контроль доступа и политика удаления.
