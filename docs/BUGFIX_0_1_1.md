# Исправление v0.1.1 — одновременная отправка счетов

## Симптом
Два счета одного поставщика с одинаковым номером показывались с риском 0 вместо 0 и 60.

## Причина
В исходной реализации чтение существующих счетов и запись нового счета не были
сериализованы. Два параллельных запроса могли одновременно увидеть отсутствие дубликата.

## Исправление
- PostgreSQL: блокировка строки поставщика `SELECT ... FOR UPDATE` на время проверки
  и записи счета. Второй запрос ожидает завершения первого.
- SQLite: `BEGIN IMMEDIATE` до первого чтения для блокировки конкурентной записи.
  Это блокирует все конкурирующие записи на время операции и подходит для учебной версии,
  но не предназначено для высоконагруженной системы.
- В HTML-форму добавлена блокировка двойного нажатия кнопки.
- Добавлены тесты на конкурентные и последовательные запросы.

## Важные ограничения
- Уже созданные счета с 0 баллов **не пересчитываются автоматически**.
- Приложение демонстрационное: без аутентификации и CSRF-защиты, не публикуйте его
  в интернете и не загружайте реальные платежные реквизиты.
- Не переписывайте локальную базу `invoiceshield.db` при обновлении.
