# Урок 7. Защита от подбора паролей

Argon2id защищает хеши в базе, но не ограничивает онлайн-попытки входа. В v0.7 появились серверные счётчики для пары **нормализованный логин + IP-адрес клиента** и 15-минутная блокировка после пяти ошибок.

## Путь запроса

`POST /login` → login-CSRF → нормализация логина и проверка длины → блокировка транзакции → проверка лимита → проверка пароля Argon2id → запись ошибки или создание сессии.

SQLite использует `BEGIN IMMEDIATE`, PostgreSQL — transaction-scoped advisory lock. Блокировка нужна, чтобы параллельные запросы не потеряли обновления.

Код: `app/models.py:LoginThrottle`, `app/auth.py:login_throttle_state`, `app/routes_auth.py:post_login`. Тесты: `tests/test_hardening.py`.

## Ограничения

- Это ограничение **на пару логин/IP**, а не защита от распределённого перебора с множества адресов.
- Спрей паролей по множеству логинов и атаки через proxy требуют защиты на gateway; заголовок `X-Forwarded-For` не используется без настроенного доверенного прокси.
- Временная блокировка аккаунта может быть вызвана посторонним с того же IP.
- SHA-256 ключа — псевдонимизация, не анонимизация. Журнал SecurityEvent требует политики хранения.
- Нужны HTTPS, MFA, monitoring и оценка безопасности перед production.

## Практика

В локальной тестовой среде выполни `python -m pytest tests/test_hardening.py -q`. Пять последовательных ошибок дают HTTP 429 с `Retry-After: 900`; правильный пароль до истечения блокировки не отменяет ограничение. Не тестируй перебор на чужих сайтах.
